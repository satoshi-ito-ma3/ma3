# 導入動機 01 — 止まらないエージェント（runaway agent）

> **「なぜ MA³ を入れるのか？」に、哲学ではなく "現実の失敗" で答えるシリーズ。**
> 第1回は、自律エージェントで最も広く・最も高くつく失敗：**止まらないこと**。

---

## 1. 現実に起きる失敗（シナリオ）

あるチームが、問い合わせ対応を自動化する LLM エージェントをデプロイした。
ツール（検索・API呼び出し・再試行）を自分で選んで動く、よくある構成。

ある日、外部 API が「成功でも失敗でもない曖昧な応答」を返し始める。
エージェントは「まだ終わっていない」と判断し、**もう一度試す**。また曖昧。**もう一度**。

- 誰も「何回まで」を決めていなかった。
- エージェント自身に「もう十分やった、止まれ」と言う仕組みがなかった。
- 監視に気づくまでの数時間で、API コールは数万回。請求は跳ね上がり、
  下流の外部サービスには（こちらが意図しない）大量アクセスが流れ込んだ。

これは架空の極端例ではない。自律エージェントの典型的な事故は派手な「暴走 AI」ではなく、
**地味な無限ループ・無限リトライ・無限の自己呼び出し**である。原因はいつも同じ：

> **「いつ終わるか」を、外側の運用ルールに頼り、エージェントの構造に持たせていない。**

タイムアウトや最大リトライ回数を"設定で"足すことはできる。だが設定は外付けで、
忘れられ、新しい経路で迂回され、`while True` の前では無力なことがある。
**止まることが、設定ではなく構造になっていない。**

---

## 2. MA³ が変えること

MA³ の第1原則は、エージェントに **有限の生命（`life`）** を持たせ、
それを **単調減少** させ、**0 で必ず終了（END）** させる：

```text
原則1（有限性）：life は単調減少し、0 で END に落ちる。
              ＝ 構造的に「永遠に動き続ける（暴走する）」ことができない。
```

ここが効きどころ：**「止まる」がオプションではなく、作りつけの帰結になる。**

- リトライが曖昧な応答で進まなくても、`life` は減り続ける。
- 何の例外も握りつぶされても、`life` が 0 になればループは終わる。
- 「いつ止めるか」を運用者の注意力に頼らず、**個体の寿命そのものに埋め込む。**

実装上の対応は `src/mortal_agent.py` の `life` 単調減少＋END 遷移。
これは MA³ の7原則の中で **唯一、実験で棄却されていない "作りつけで真" な性質**である
（後述）。哲学的な主張ではなく、構造に組み込まれた歯止めだから強い。

---

## 3. 正直なスコープ（過大主張しない）

MA³ の価値を誠実に切り分ける。

- ✅ **言えること：** 「個体の寿命で上限を強制し、構造的に止める」設計は、
  外付けタイムアウト依存より頑健になりうる。第1原則は実装で検証済みの構造的性質。
- ⚠️ **言えないこと：** 「"死" がエージェントを賢くする／誤りを減らす」とは、
  まだ言えない。本リポジトリの[実験001](../README.md#実験デモを実験にする)は、
  自説（有限性が性能で勝つ）を**支持しなかった**——効いていたのは "死" そのものではなく
  **忘却・直近重視・有限窓** という情報処理上の制約だった。
- 🧭 **だから本動機の主張は「賢さ」ではなく「安全な停止」に限定する。**
  止まらない失敗を、止まる構造で防ぐ。それ以上は約束しない。

これは「死は万能」ではなく「**有限性は"止まること・忘れること・コミットすること"を
強制する制度として価値がある**」という、実験001の結論と地続きの主張である。

---

## 4. 監査の問いへ（Agent Safety Audit の種）

この導入動機は、そのまま **エージェント安全監査の1項目** になる：

> **監査質問 #1：** あなたのエージェントは、外部設定（タイムアウト・最大リトライ）を
> すべて取り除いても、**有限ステップで必ず停止する** と構造的に言い切れるか？
> できないなら、それは "止まらない失敗" の候補である。

- **不合格の兆候：** `while True`／無上限リトライ／停止条件が「タスク完了の自己判断」だけ
  に依存／停止が運用設定（外付け）にしか存在しない。
- **MA³ 流の合格基準：** 個体に有限の予算（寿命・トークン・ステップ・コスト）を持たせ、
  それを単調に消費し、枯渇で**必ず**終端へ落とす。停止が"作りつけ"であること。

将来の `ma3-auditor` は、この質問をコード／構成に対して機械的にチェックする道具として
育てられる。本ドキュメントはその**最初の1問**の根拠である。

---

## 5. 30秒で体験する

```bash
python -m src.mortal_agent
```

`life` が単調に減り、**0 で必ず死ぬ**様子が出力される。LLM も API キーも不要。
「何があっても、これは永遠には動かない」を、自分の目で確かめてほしい。
